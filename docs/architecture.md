# gueiz の組み立て方

エンジンに手を入れる人向け。**なぜそうなっているか**を書きます。
何があるかは `cargo doc --workspace --open` のほうが正確です。

## 1. 全体の形

```
                 ┌──────────────┐
                 │ gueiz        │  窓口（再輸出のみ）+ 例
                 └──────┬───────┘
          ┌─────────────┼─────────────┐
          │             │             │
   ┌──────▼─────┐ ┌─────▼──────┐ ┌────▼─────────┐
   │ gueiz-2d   │ │ gueiz-3d   │ │ gueiz-window │
   └──────┬─────┘ └─────┬──────┘ └────┬─────────┘
          └──────┬──────┘             │
           ┌─────▼──────┐             │
           │ gueiz-gpu  │             │
           └────────────┘             │
                 ┌────────────────────▼──┐
                 │ gueiz-core（依存なし） │
                 └───────────────────────┘
```

`gueiz-window` は **GPU を触りません**（`wgpu` に依存していません）。
`gueiz-gpu` は**窓を知りません**。描き先は呼ぶ側が渡します。
この 2 つが混ざらないので、窓なしで画像に描くだけの使い方（例のほとんど）が
そのまま成り立ちます。

### 2D と 3D をどこで分けたか

置き場所の基準は 1 つだけです。**そのコードが「次元」を口にするか。**

| 何をしているか | 次元 | 置き場所 |
|---|---|---|
| 確保する・束ねる・提示する | 言わない | `gueiz-gpu` |
| できあがった画像を加工する | 言わない | `gueiz-gpu` |
| 形を作る | 言う | `gueiz-2d` / `gueiz-3d` |
| 光を当てる・奥行きを解く | 言う | `gueiz-3d` |

**`DrawManager` は共通化していません。** 先に共通化しようとして、
パラメータで吸収できないことが分かったためです。3D を素直に書き下ろしてから
比べたところ、本当に違ったのは 4 点でした。

| | 2D | 3D |
|---|---|---|
| 頂点の渡し方 | ストレージバッファ + 番号 | 頂点バッファ + 索引 |
| カリング | 境界円 × クリップ矩形 | 境界球 × 錐台 6 面（世界空間） |
| 奥行き | 深度なし。z は並べ替えの鍵 | 深度バッファ |
| 行列 | `camera * object` を畳む | 世界行列とカメラを分ける |

逆に**同じだった部分は後から引き上げました**。増分アップロード
（`gpu::instance::InstanceUploader`）と形のプールの積み直し（`gpu::pool::Pool`）が
それです。

> **進め方**: 似ているものを先に共通化しない。**2 つ実物を書いてから、
> 本当に同じだった部分だけを引き上げる。** 早すぎる共通化は、
> どちらの側も歪めます。

## 2. 描画の中核 — GPU-driven

ここが `gueiz` のいちばん大事なところです。**図形が何種類あっても、
CPU が出すドローコマンドは 1 回。**

```
CPU                         GPU（コンピュートパス）        GPU（描画）
─────────────────────────   ──────────────────────────    ────────────────
図形の記述を上げる      →   インスタンスごとに 1 スレッド
複製の素データ          →     ① 行列を組む
（位置・回転・拡大・色）        camera * object * instance
※ 行列は計算しない            ② 画面外なら捨てる
                               ③ 生き残りを詰めて書く
                               ④ instance_count を
                                  atomicAdd で増やす
                                                      →   multi_draw_indirect
                                                          （引数は GPU が書いた）
```

### なぜ CPU が行列を組まないのか

インスタンスが 100 万個あれば、行列も 100 万個です。CPU で組むと、
掛け算より**転送**が効いてきます。素データ（位置・回転・拡大・色）なら小さく、
組み立ては並列に向いているので GPU が得意です。

### なぜドローを「図形ごと」に分けるのか

1 回の `draw` で全インスタンスを描くと、**頂点数が全図形の最大値に揃います。**
頂点 3 個の三角形も、頂点 96 個の折れ線に合わせて 96 回頂点シェーダを起動し、
93 回ぶんを捨てることになります。

図形ごとにドローを分けるとこの無駄が消えます。CPU から見たコマンドは
`multi_draw_indirect` 1 回のままで、**ドローの中身は GPU が決める**ので、
CPU の負荷は増えません。

### バッファの分担

| | usage | 誰が書くか |
|---|---|---|
| 形状プール | `STORAGE \| COPY_DST` | CPU（形が変わったときだけ） |
| 図形の記述 | `STORAGE \| COPY_DST` | CPU（毎フレーム、図形の数ぶん） |
| インスタンス入力 | `STORAGE \| COPY_DST` | CPU（**書き換わった図形のぶんだけ**） |
| インスタンス出力 | `STORAGE \| VERTEX` | **GPU** |
| インダイレクト引数 | `STORAGE \| INDIRECT \| COPY_DST` | CPU が初期化、**GPU** が個数を書く |

### 変わっていないものを送り直さない

`DrawManager::prepare` は、汚れた図形のぶんだけを上げ直します
（`gpu::instance::InstanceUploader`）。並びが変わらなければ、
**触った図形の範囲だけ**を `write_buffer` します。

効き方は `bench_draw` で測れます。

```bash
cargo run --release -p gueiz --example bench_draw
```

### 承知のうえの制約

`atomicAdd` で詰めるので、**同じ図形の中では複製の描画順が決まりません**。
半透明が重なると、フレームごとに結果がわずかに揃わないことがあります。
図形どうしの前後は z の並べ替えで決まるので、そちらは安定します。

## 3. 2D

### 形にする（`gueiz-2d::tessellate`）

塗りも線も三角形リストに開いてから積みます。線を `LineStrip` トポロジで描くと
パイプラインが分かれてドローが増えるので、**線も多角形として開きます**。

塗りは耳刈り取り（ear clipping）です。

- 複数の輪郭を**包含の深さ**で外周と穴に振り分ける（偶数が外周、奇数が穴）
- 穴は幅 0 の橋で外周につないでから刈る
- 刈り取りが止まったら、対角線で分割して続ける（earcut の split 相当）

**自己交差する輪郭は直しません。** 入力が正しい前提です。

### 文字（`gueiz-2d::font` / `text`）

グリフをテクスチャに焼かず、**輪郭をそのまま図形にします**。理由は
すでにあるもので済むからです。穴（`o` `a` `e`）も離れた輪郭（`i` `=`）も
テッセレータがそのまま扱えます。

同じ字は形を 1 つだけ登録し、出てくるたびに複製を足します。
**`e` が 50 回出ても、形は 1 つ・複製が 50 個。**

代わりに**小さい字はギザギザになります**（アンチエイリアスが無いため）。
UI の 12〜16 px を綺麗に出すには SDF が要ります。いまは入っていません。

### 書式（`gueiz-2d::format`）

`§[red]` のようなコードを文字列に埋めます。
**`TextRenderer::write` は書式を読みません。** 読ませたいときだけ
`Formatted::parse` を通します。外から来た文字列をそのまま解釈すると、
他人が書式を差し込めるためです。

太字・縁取り・影は別の書体を持っていないので、**同じ形をずらして重ねて**
作っています。形は共有されたままなのでドローは増えず、増えるのは複製だけです。

### 大きさは 2 組ある

`TextLayout` / `TextSize` が返す幅と高さは 2 組あります。

- **送り幅**（`width` / `height`）— 次の字をどこに置くか
- **塗られる範囲**（`ink`）— 実際に色が乗る範囲

斜体・影・縁取り・太字・丸い端は送り幅の外に出ます。
**右に寄せる・背景を敷く・画面に収まるか見るときは `ink`** を使わないと切れます。

### 色の空間

**色は sRGB で受け取り、線形で計算し、sRGB で出します。**

```
sRGB で書く → 頂点シェーダで線形へ → 掛ける・混ぜる・合成する（線形）
            → GPU が sRGB へ戻して書き出す
```

直さないと `0.5` が真ん中の灰色ではなく **sRGB 188** で出ます。
`NamedColor` は 16 進から作っているので、`gray`（`#808080`）が
`#bcbcbc` に見える、という食い違いが起きていました。

**両端（0 と 1）は変換しても動きません。** だから原色だけ見ていると
気づけません。中間調だけが静かにずれます。

**不透明度は変換しません。** 光の量ではなく覆う割合なので、
ガンマを掛けると半透明がずれます。

窓なしの例も**窓と同じ sRGB の描き先**に揃えてあります。揃っていないと、
例が通っても窓では色が違う、という状態を見逃します。

### エフェクト（`gueiz-2d::effect`）

VFX Graph と同じ組み立て方です。効く場所は 3 段あり、
**この順番はハードウェアが決めていて動かせません。**

```
Shape（CPU・テッセレーション）→ Transform（コンピュート）→ Color（フラグメント）
       形を作る                     位置を動かす              色を変える
```

`Block` は自分がどの段で効くかを知っていて、`EffectStack` は段ごとに
別の列として持ちます。**順番が意味を持つのは同じ段の中だけ**です。

画面全体に掛けるものは 4 つめの段として `gpu::post` にあります。
分かれ目は「**すでに描かれた画素を読む必要があるか**」です。

## 4. 共通層（`gueiz-gpu`）

### ヒープ（`buffer`）

境界タグ方式のフリーリストです。確保・解放・隣と合流。
GPU バッファを 1 本取って、その中を自分で切り分けます。

### 絵の載せ方（`gueiz-gpu::atlas`）

テクスチャの口は**シェーダに 1 つだけ**です。1 ドローに畳む以上、
全図形が同じバインドグループを共有するので、増やせません。

```wgsl
var sprite_sheet: texture_2d_array<f32>;   // 口はここだけ
```

そこで層を「ページ」として使い、その中に大きさの違う絵を敷き詰めます。
どの絵かは「ページ番号 + 切り出し範囲」で指すので、図形側の仕組みは
そのままです。

**登録と確定を分けてあります。** `load_texture` は画素を預かるだけで
GPU を触らず、`commit_textures` が**全部まとめて**詰めます。
詰め込みは全部見てからのほうが密になるためで、高い順に並べ替えてから
棚に載せます。

ページが足りなくなったら、層の多いテクスチャを作って
**GPU 上で古いページを写します**（`copy_texture_to_texture`）。
画素を CPU に持ち続ける必要がありません。

#### 実行中の出し入れ

`remove_texture` は棚の中に**空き区間**を返します。区間は隣とつながり、
棚の右端まで空けば端が戻り、いちばん上の棚が空になれば棚ごと降ります。
次に入れる絵は**空いた穴から先に**埋めるので、出し入れを繰り返しても
ページは伸びません（50 回回して 1 ページのまま、を例で見ています）。

消しても**画素は消しません。** 誰も読まないので、消すためだけに
書き込むのは無駄です。次の絵がそこに入ると上書きされ、余白まで
塗り直されるので古い色が漏れることもありません。

**貼ってある図形は勝手に剥がれません。** 消した絵を指したままの図形は、
そこに入った別の絵を映します。消す前に `Object::no_sprite` で剥がします。

**詰め直しはしません。** 穴に入らない大きさばかりが来ると隙間が残るので、
そのときは `clear_textures` からやり直します。

#### 透明なところに色をにじませる

シェーダは**普通のアルファのまま**絵を読み、出す直前にだけ乗算済みへ直します。
ところが**ハードウェアの線形補間は乗算済みでないと正しくありません。**

赤の不透明画素と透明黒が隣り合うと、中間は `(127,0,0,127)` になり、
出す段で `rgb * a` して `(64,0,0)`。**本来の半分の明るさ**で縁が黒ずみます。

そこで読み込むときに、**透明な画素の RGB を近いほうの色で埋めます**
（アルファは触りません）。見た目は変わらず、補間に使われる色だけが直ります。
`atlas_test` の 5 番が、境目の赤を 49 ではなく 112 で読めることを見ています。

#### 余白

アトラスでは絵が隣り合うので、補間が**隣の絵**を舐めます。
各絵のまわりを自分の縁で伸ばして挟みます。

縮小用の段を作ると段を下るほど隣が近づくので、**余白は自動で
`2^(段数-1)` まで広げます**。置き場所も同じ刻みに揃えるので、
段ごとの位置が割り切れ、絵 1 枚ぶんの段を独立に書き込めます。

### 窓の大きさへの合わせ方（`camera::ScaleMode`）

`Fixed`（絶対）が既定。1 単位 = 1 画素のままで、窓を広げると見える範囲が広がります。
相対は 4 つに分かれていて、**縦横比が窓と合わないときに何を諦めるか**が違います。

相対にすると**マウスの画素位置と図形の座標が一致しなくなる**ので、
`Camera::screen_to_world` を通します。

### リソース置き場（`resource`）

生成的ハンドル（slot map）です。消した枠は使い回しますが、**そのとき世代が
1 つ進むので、古いハンドルは新しい中身を掴みません**。
これが無いと、消したフォントのハンドルがたまたま同じ枠に入った別のフォントを
指してしまいます。気づきにくい壊れ方をするので、世代を持つ価値があります。

## 5. 確かめ方

**2 段構え**です。

| | 何を見るか | GPU |
|---|---|---|
| 単体テスト | 計算だけで決まること | **要らない** |
| 例 | GPU まで届いているか | 要る |

単体テストは行列・テッセレーション・文字の並べ方・書式の解釈・ヒープの確保を見ます。
GPU を触らないので `cargo test --workspace` はどこでも通ります。

例は**描いた画素を読み戻して自分で確かめ**、合っていなければ落ちます。
`-- --window` を付けると結果を窓に出します。

```bash
cargo test --workspace
cargo run -p gueiz --example text_format_test
cargo run -p gueiz --example text_format_test -- --window
```

### テストの書き方

このコードのテストは**壊れ方を名前にしています**。

```rust
/// 消した枠は使い回されるが、古い取っ手が新しい中身を掴んではいけない。
/// ここが世代の要点。
#[test]
fn a_reused_slot_does_not_answer_to_the_old_handle() {
```

「何を守っているか」と「守らないと何が起きるか」が読めるようにしてください。
`fn test_handle()` のような名前は、落ちたときに何も教えてくれません。

**テストの中で本番のロジックを写さないこと。** 写すと写しのほうを試すことになります。
`gueiz-2d::text` の書式の積み上げは、本番と同じ `FormatStack` を通しています。

### GPU 無しで並べ方を試す

`gueiz-2d::text` には `Metrics` という内部の継ぎ目があります。
`Font` が実装していますが、テストでは作り物を差し込むので、
**フォントを読まなくても**行の高さや線の切れ目を検算できます。

## 6. いま入っていないもの

コード側にも書いてありますが、まとめておきます。

| | 状況 |
|---|---|
| 小さい字のアンチエイリアス | MSAA 4x では足りない。SDF が要る |
| 文字の整形 | 合字・アラビア語の連結・縦書き・双方向は無い |
| 自己交差する輪郭 | 直さない。入力が正しい前提 |
| 3D のエフェクト段 | 無い |
| 3D と `Renderer` のつなぎ | 深度添付を自分で用意する必要がある |
| 3D の法線 | 非一様な拡大で崩れる |
| 頂点の詰め方 | `Vertex` は 48 バイト中 20 が余っている |
| アトラスの詰め直し | しない。穴に入らない大きさが続くと隙間が残る |
| 絵の差し替え | 同じ場所への上書きは無い。消して足すと場所が変わる |
| 画像の復号 | PNG も JPEG も読まない。RGBA8 を渡す |
| 音（`gueiz-sound`） | 未着手 |

## 7. 書くときの約束

- **ドキュメントは日本語。** 識別子は英語
- コメントは「何をしているか」ではなく**「なぜそうしたか」**を書く。
  とくに、**そうしなかった選択肢**と**そうしないと何が壊れるか**
- 数字を書くときは測る。見積もりなら見積もりと書く
- 承知のうえの制約は、隠さずコードのそばに書く
